### 未覆盖语句性质说明（未做排除/弱化）

未覆盖语句全部为以下两类，均无法在依赖健康的真实 MySQL/Redis 环境下触达：
1. `if err != nil` 的 DB/Redis 故障防御分支（Scan/One/Insert/Update/Do 返回错误的路径）。
   项目未引入接口级 mock 基建，真实依赖正常时这些分支不可达。
2. `main.go` 的服务启动装配语句（`s.Run()` 阻塞调用，不可在进程内测试）。

测试执行策略说明：
- 集成测试（internal/cmd，启动真实 HTTP 服务覆盖全部路由与中间件）与各 logic 包单元测试
  并行运行会产生测试数据竞争，质量门禁统一使用 `go test -p 1`（包间串行）。
- 已尝试 `go test -race`：本机无 CGO 工具链（gcc 缺失），见 docs/plans/assumptions.md 假设 7；
  并发安全由 Lua 原子脚本、DB 条件更新（影响行数判定）与并发单元测试（10 goroutine 抢 3 名额等）保障。
